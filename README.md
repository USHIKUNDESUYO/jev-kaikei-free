仕訳は確認用の下書きです。モックの結果や確信度から、会計・税務処理の正確さや専門家の作業全体を代替する効果を保証することはできません。この配布には認証情報、顧客資料、モデルの重み、私用設定、元の非公開Git履歴を含めません。

TypeSafe AI の判断モデル **Jev** にレシートを見せて、勘定科目・消費税区分・私的支出かどうかを判定させ、仕訳を作るローカルツールです。
レシートがベルトコンベアで流れ、Jev の前で判定され、確信度がしきい値以上なら勘定科目のカゴへ、未満なら「裁きの間」（人の確認）へ落ちます。
「裁きの間」に落ちたものは 1 枚ずつ借方・貸方を直して確定し、仕訳CSVに出せます。

画面の言葉は魔界寄りにしてありますが、中身は普通の会計です。

| 画面の言葉 | 会計の言葉 |
|---|---|
| 選別の間 | 仕分け画面 |
| 裁きの間 | 人の確認（レビュー） |
| 金庫入り | 自動仕訳 |
| 帳面を持ち込む | 資料（CSV / JSON）を読み込む |
| 羊皮紙 | レシート |
| 帳簿の悪魔 | Jev |

仕訳CSV の「状態」列は会計の言葉（自動仕訳 / 要確認 / 確認済み / 修正して確定 / 保留）のままです。

Jev は文章を生成せず、渡した選択肢の中から確率と確信度つきで答えを返すモデルです（2026-09-15 公開、`jev-1.13.0`）。
APIの料金は提供元の契約と利用量によります。画面の費用表示は推計であり、請求額の上限を設定する機能はありません。

## 使い方

1. **帳面を持ち込む**: CSV / JSON ファイル、見本の帳面、手で書く のどれか。
2. 読み込んだ順に Jev が判定し、ベルトに流れてカゴに落ちます。Space で一時停止、→ で 1 枚だけ進める。
3. **金庫入りのしきい値**（既定 0.80）を動かすと、その場で 金庫入り / 裁きの間 の振り分けが変わります。
4. **裁きの間**タブで、裁き待ちの分を 1 枚ずつ確認。Enter で確定、← → で移動、S で保留。「金庫入りも含めて全部見る」で自動分も見直せます。
5. **仕訳CSV** で出力（UTF-8 BOM 付き。Excel でそのまま開けます）。列: 日付, 借方勘定科目, 借方金額, 貸方勘定科目, 貸方金額, 税区分, 内消費税, 摘要, 確信度, 状態。

読み込んだデータと確定した仕訳はブラウザーのlocalStorageに残ります。「全部クリア」で取引・判定・仕訳・使用量を空にしても、事業内容などの設定は保持されます。

### 保存したJSONを読み戻す

「JSON」で保存したファイルを「帳面を持ち込む」から選ぶと、取引・判定結果・確認済みの仕訳・保留を復元できます。確認時に直した金額と摘要も引き継ぎます。保存JSONの復元では外部APIへ再送せず、未判定の取引は未判定のまま残ります。

復元した取引は現在の取引へ追加します。同じファイルをもう一度読み込むと、その分も追加されます。既存の取引や現在の設定、しきい値は変えません。復元した自動仕訳も、通常の操作でしきい値を変更すると再び振り分けられます。

判定と表示が動いている間は、終了後に読み込んでください。形式が不正な保存JSONは全件を拒否し、現在の取引を保ちます。通常の入力用JSONとCSVも引き続き読み込めます。

### ブラウザーの自動保存に失敗した場合

容量不足や保存が許可されていない設定では、画面上部に案内を表示します。取引と確認記録はこのタブに残りますが、今回の変更が再読み込みで失われる可能性があります。「JSONを保存」でファイルへ保存してから閉じてください。JSONの保存後も、自動保存の成功は確認できていないため案内を残します。

容量や設定の問題を解消したら「自動保存を再試行」を押してください。ブラウザーへの保存が成功すると案内が消えます。保存JSONの復元時も、自動保存の成否を表示します。復元失敗や未保存の案内がある間は、再読み込みや「全部クリア」を避けてください。

### 入力 CSV の列

列名は柔軟に拾います（UTF-8 / Shift_JIS どちらでも可）。

| 意味 | 認識する列名の例 |
|---|---|
| 日付 | 日付, 取引日, 利用日, date |
| 支払先 | 支払先, 店名, 取引先, 相手先, payee（なければ 摘要 を支払先として使う） |
| 摘要 | 摘要, 内容, メモ, 備考, memo, description |
| 金額 | 金額, amount。または 出金/出金額 と 入金/入金額 の 2 列 |
| 支払方法 | 支払方法, 決済方法（現金 / カード / 銀行 / 個人）。なければ設定の既定値 |
| 区分 | 区分, 収支（支出 / 収入）。なければ支出扱い |

`samples/receipts_sample.csv` と `samples/receipts_sample.json` が見本です。

## Jev への聞き方

1 レシート = 1 リクエストで、3 つの質問を同時に投げます（Jev は質問を並列に評価するので、質問を増やしても時間はほぼ増えません）。

| 質問 | 種類 | 内容 |
|---|---|---|
| `account` | Choice | 勘定科目マスタ（支出 37 択 / 収入 12 択、事業形態で増減）から 1 つ。各選択肢に `what / examples / not_for` を付けて混同を減らしています |
| `tax` | Choice | 課税 10% / 軽減 8% / 非課税 / 対象外 |
| `is_private` | Noul | 私的な支出・資金移動である確率 |

state には日付・支払先・摘要・金額・支払方法・収支を渡します。相手先と事業内容も、入力されている場合は含めます。Jev は関係ない情報が混ざると精度が落ちるためです。

判定後にコード側でルールを足しています。

- 消耗品費で 10 万円以上 → 固定資産（工具器具備品）や少額減価償却資産の特例を検討、と注意して人の確認へ
- 会議費・接待交際費で 1 人 1 万円以下 → 「1万円ルール」のヒント。会議費で 1 万円超は人の確認へ
- 私的支出の確率が 60% 以上なのに課税の科目（経費・売上） → 人の確認へ（カード引落しや預金利息でも 55% 前後が出るので、そこには適用しない）
- 口座間振替・内容不明（仮払金・仮受金） → 必ず人の確認へ
- 税区分は科目が課税のときだけ Jev の答えを採用（確信度 0.6 未満なら 10% を既定に）。租税公課や給料など固定の科目はマスタの値

貸方（収入なら借方）は支払方法で決めます: 現金 → 現金、銀行 → 普通預金、カード → 未払金、個人立替 → 事業主借（法人は役員借入金）。

## 勘定科目を変える

`jev_kaikei/accounts.json` を編集します。`code` は Jev に渡す ID（半角英数）、`what / examples / not_for` が Jev の判断材料です。
`entity` で個人事業主 / 法人専用、`mode` で売上の計上方法（入金時 / 請求時）を切り替えられます。

## 限界と注意

- OCR は入っていません。レシート画像から文字を起こす部分は別途必要です（Jev はテキスト専用モデル）。
- Jev は日本語では英語より精度が下がると公式が案内しています。しきい値は自分のデータで試しながら決めてください。
- 金庫入り（自動仕訳）もあくまで下書きです。確定前に必ず目を通してください。
- 仕訳CSV は汎用形式です。freee や マネーフォワード のインポート形式にはまだ合わせていません。

## CSV出力の文字列

数式の先頭と解釈され得る文字列には、CSV出力時に先頭へアポストロフィを付け、セル全体を引用符で囲みます。半角・全角の数式記号、先頭のタブや改行、記号の前の空白が確認対象です。金額などの数値、通常の文字列、元データとJSON出力は保持します。

表計算ソフトで編集・保存したCSVでは、この保護が失われる場合があります。再保存後の数式無効化や、すべての会計ソフトへの取込互換性を保証するものではありません。元の文字列を使う処理にはJSON出力を利用してください。[OWASPのCSV Injectionの説明](https://community.owasp.org/attacks/CSV_Injection)も参照できます。

CSV出力の回帰試験は、Node.jsがある環境で`node --test tests/test_csv_export.cjs`を実行します。アプリの利用自体にNode.jsは不要です。

## 金額が大きすぎる場合

この版では、円単位に丸めた金額が9,007,199,254,740,991円を超える場合や、数値が無限大になる場合に、取り込みや確認を止めます。CSV・JSONの読み込みでは、そのファイルの取引を追加せず、既存の取引を保ちます。表示された件数を手がかりに、元ファイルの金額を直してから読み直してください。

手入力では入力欄の下に説明を表示し、入力内容を残します。確認画面でも、その取引を確定せず、修正前の金額と確認状態を保ちます。以前の版で保存された不正な金額を、自動で復元・修復する機能はありません。

## 入力ファイルの形式を直す場合

CSVの引用符が閉じていない場合、項目の途中に引用符がある場合、閉じた引用符の後に余分な文字がある場合は、ファイル全体を読み込まずにエラーを表示します。データの列数も、ヘッダーの列数とそろえてください。末尾の空欄にはカンマが必要です。引用符で囲んだ項目内のカンマ・改行・二重引用符、空行、UTF-8のBOMは読み込めます。

入力用JSONは取引の配列、または`items`・`records`に取引の配列を持つ形式を使います。各取引の日付・支払先・摘要・支払方法・区分は文字列、金額は数値または文字列にしてください。省略した文字列項目や`null`は空欄として扱います。形式の不備があると、先に並ぶ正常な取引も含めて追加せず、現在の取引を保ちます。

エラーの「データ○件目」は、空行を除く取引の順番です。CSVの項目内に改行がある場合、エディターの行番号とは異なります。元ファイルを直して再度読み込んでください。数値に変換できない金額や0円の行を読み飛ばす従来の動作は残っています。この検査は、取引の実在や会計処理の正確さを確認するものではありません。

入力形式の試験は`node --test tests/test_input_format.cjs`で実行できます。保存したJSONの復元、金額の上限、自動保存失敗の案内も、既存の試験で確認しています。

## 存在しない日付を読み込んだ場合

`2026-02-30`や`1900-02-29`のように、年・月・日として読めても暦に存在しない日付は取り込み前に止めます。CSV・入力用JSON・保存JSONの取込対象に不正な日付があると、ファイル全体を追加せず、現在の取引と確認記録を保ちます。エラーに表示された取引の日付を元ファイルで直し、再度読み込んでください。

対象は、先頭が4桁の年と月・日で表された日付です。ハイフン、スラッシュ、年月日の表記を扱い、うるう年を確認します。`2024-02-29`や`2000-02-29`は読み込めます。空欄や「日付不明」など、日付として認識しない文字列の従来の扱いは変えていません。取引日の正しさや、すべての表記を確認する機能ではありません。

試験は`node --test tests/test_date_guard.cjs`で実行できます。既存取引を残したまま、不正な日付を含むファイルの読み込み、直接の取引追加、正常なうるう日を確認しています。

## JSONの同じ項目名が重複している場合

同じオブジェクトに`"amount":1100,"amount":2200`のように同じ項目名が2回あると、読み込み前に停止します。入力用JSONと保存JSONのどちらも対象です。後の金額や確認状態を黙って選ばず、ファイル全体を追加せずに現在の取引と確認記録を保ちます。エラーに示された項目名を元ファイルで確認し、使う値を1つに直してから読み直してください。

入れ子になったオブジェクトや、アプリが使わない項目も確認します。Unicodeエスケープで表した項目名は、読み戻した名前で比較します。別々の取引に同じ項目名がある場合や、摘要の文章に項目名を書いた場合は重複とは扱いません。正常な保存JSONは、確認状態を引き継ぎ、外部APIへ再送せずに復元できます。

対象は読み込むJSONファイルです。CSV、外部APIの応答、ブラウザー内に残る古い保存データの自動修復は含みません。試験は`node --test tests/test_json_fields.cjs`で実行できます。

## CSVの列名が重複している場合

`支払先,金額,金額`のように同じ列名が2つあるCSVは、取り込み前に停止します。エラーに列名と列の位置を示し、ファイル全体を追加せずに現在の取引と確認記録を保ちます。元ファイルで、それぞれの列が何を表すかを確認し、列名を直してから読み直してください。

列名は、空白と二重引用符を除き、英字の大文字・小文字を区別せずに比較します。`AMOUNT`と`amount`、`金額`と`金 額`も重複として扱います。アプリが使わない列も確認します。空欄の列名、別の名前である`金額`と`amount`、出金額と入金額を分けたCSVは、従来どおり読み込めます。別の名前から同じ項目に対応する列を探す優先順位は変更していません。

対象はCSVのヘッダーです。取引の二重計上や、金額・会計処理の正確さを確認する機能ではありません。試験は`node --test tests/test_csv_headers.cjs`で実行できます。

## CSVの同じ行に出金と入金がある場合

出金と入金の両方に正の金額がある行は、取り込み前に停止します。例えば、同じ行に出金1,100円と入金2,200円があると、片方だけを選ばず、ファイル全体を追加せずに現在の取引と確認記録を保ちます。エラーに示されたデータの位置を元ファイルで確認し、金額と収支を直してから読み直してください。

出金か入金のどちらかだけに正の金額があるCSVは、従来どおり読み込めます。反対側が空欄や0円の行も扱えます。対象は出金・入金の列が両方あるCSVです。区分の指定や金額の丸め方、負の金額の扱い、別名の列を探す優先順位は変更していません。試験は`node --test tests/test_bank_direction.cjs`で実行できます。

### CSVの金額を数値にできない場合

金額・出金・入金の列に「不明」のような数値にできない文字や、無限大などがあると、該当するデータの位置と列名を表示し、ファイル全体の取り込みを止めます。現在の取引と確認記録は保持します。元ファイルの金額を確認してから読み込んでください。片方の入出金を採用する場合も、もう片方や金額列の不正な値を見逃しません。

空欄や0円の扱い、引用符で囲んだ「1,100」、全角数字と通貨記号、金額の丸め方は従来どおりです。金額ではない備考などの文字列には、この確認を適用しません。

通常の取引JSONでは、`amount`・`金額`に数値にできない文字や無限大があると、該当するデータの位置と項目名を知らせ、ファイル全体の取り込みを止めます。両方の項目がある場合は、それぞれを確認します。現在の取引と確認記録は保持します。元ファイルの金額を直してから読み込んでください。空欄・未指定・0円の扱い、金額の丸め方、保存JSONの復元は従来どおりです。

保存JSONの仕訳金額が0円の場合は、該当するデータの位置を知らせ、ファイル全体の復元を止めます。現在の取引と確認記録は保持します。元ファイルの仕訳金額を確認し、0円を含めないファイルを読み込んでください。正の金額を持つ確認済み・自動・要確認・保留の復元、確認時に直した金額の引き継ぎ、未判定の取引の復元は従来どおりです。通常の取引JSONにある0円の行の扱いは変えていません。
